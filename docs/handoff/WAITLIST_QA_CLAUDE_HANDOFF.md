## 1. What this release is (scope)

- **In scope:** (1) **Default path:** `/join` → **full** onboarding at `/onboard/*` (all original model/pro/partner questions and steps in `ModelOnboard.jsx`, `ProfessionalOnboard.jsx`, `PartnerOnboard.jsx`). (2) **Optional short forms** at `/waitlist/*` for minimal lead capture. (3) Thank-you page after waitlist submit. (4) **No** full portals for non-`Admin` users (private beta gate on authenticated routes).
- **Out of scope for waitlist-only links:** Matching, bookings, Stripe, etc. Full onboarding still persists to DynamoDB via the same `ModelProfile` / `Professional` / `Partner` models when users complete `/onboard/*`.

**Key URLs (after `npm run dev`, default Vite is usually `http://localhost:5173/`):**

| Path | Purpose |
|------|---------|
| `/` | Landing, CTA **Join Modeled** → `/join`, sign-in → `/portal` |
| `/join` | Role picker → **`/onboard/model`**, **`/onboard/professional`**, **`/onboard/partner`** (full applications) |
| `/onboard/model` (etc.) | Full multi-step onboarding (Authenticator-wrapped); deep links set `intendedRoute` then `/join` once to pick the matching role |
| `/waitlist/model` | Model waitlist form (wrapped in Amplify `Authenticator`) |
| `/waitlist/professional` | Professional waitlist form |
| `/waitlist/partner` | Partner inquiry form |
| `/thanks?role=model` (or `professional` / `partner`) | Post-submit confirmation |
| `/enter` | “Enter Modeled” — **non-admins** see private beta message; **Admin** Cognito group sees role cards |
| `/portal`, `/model-portal`, `/partner-portal` | Under authenticated shell; **non-admins** hit **`PrivateBetaLaunch`** instead of portal UI |
| `/admin` | Admin dashboard — requires Cognito group **`Admin`** (and `ProtectedRoute`) |

**Lead tagging in data:** Submissions set `adminNotes: 'waitlist_signup'` and `status: 'pending'` on `ModelProfile`, `Professional`, and `Partner` where applicable — use this to filter in DynamoDB or Admin lists.

**Relevant source files (for code review or diffs):**

- `src/App.jsx` — routes, `LandingPage`, `AuthenticatedApp`, waitlist routes, `VITE_FULL_APP_ACCESS` gate  
- `src/pages/JoinModeled.jsx` — role navigation to `/onboard/...` (default); optional `/waitlist/...` via direct URL  
- `src/pages/waitlist/ModelWaitlist.jsx`  
- `src/pages/waitlist/ProfessionalWaitlist.jsx`  
- `src/pages/waitlist/PartnerWaitlist.jsx`

- `src/pages/EnterModeled.jsx` — portal entry gate  
- `amplify/data/resource.ts` — `ModelProfile`, `Professional`, `Partner` schema + auth rules  
- `.env.example` — documents `VITE_FULL_APP_ACCESS`

## 4. Deploy test plan (step-by-step)

Exact clicks depend on host; this is the **logical** order.

1. **Branch:** Deploy from a branch you trust; tag release (e.g. `waitlist-v1`).  
2. **Build:** `npm run build` — zero errors; fix any env or import issues.  
3. **Env vars on host:** Set at minimum:  
   - `VITE_FULL_APP_ACCESS` — **unset or `false`** for public waitlist-only behavior.  
   - Any other `VITE_*` your app reads (see `.env.example`).  
4. **`amplify_outputs.json`:** CI/CD must inject the **correct** file for that environment (wrong backend = wrong Cognito pool / wrong API).  
5. **Cognito app client settings:** Hosted UI / callback URLs must include your **production origin** (e.g. `https://yourdomain.com`, `https://www.yourdomain.com`).  
6. **Cognito User Pool — `Admin` group:** Ensure at least one admin user for you to review leads in `/admin`.  
7. **SES (email):** If sign-up verification emails fail, check SES sandbox, verified identities, and Cognito email configuration (`docs/deployment/*SES*` in repo).  
8. **Smoke on prod URL:** Run sections **§3 A–E** on the **production** URL with a disposable email.  
9. **Rollback:** Know how to revert hosting to previous build if auth or API is misconfigured.

## 6. What’s often missing before “public” (checklist)

Use this as a go/no-go list with Claude or your team.

### Product / UX

- [ ] **Legal links:** Waitlist copy says “Terms & Conditions and Privacy Policy” but there may be **no in-app routes** `/terms` `/privacy` — add links to hosted legal pages or static pages before scale.  
- [ ] **404 / fallback:** Unknown paths under auth — acceptable?  
- [ ] **Copy pass:** Typos, tone, “Modeled” capitalization consistency.  
- [ ] **Accessibility:** Labels, focus order, contrast on cherry/ivory palette.  
- [ ] **Empty states:** N/A for forms; thanks page OK.

### Auth / security

- [ ] **Cognito MFA / password policy** — aligned with your risk tolerance.  
- [ ] **Rate limiting / abuse:** Public sign-up can be scripted; consider CAPTCHA or WAF later (plan deferred optional `LaunchLead` + API key pattern).  
- [ ] **Admin group:** Only trusted users in `Admin`.  
- [ ] **No secrets in repo:** `.env.local` gitignored; no service account keys committed.

### Data / ops

- [ ] **Where you read leads daily:** Dynamo console, Amplify Studio, or `/admin` models/professionals/partners — pick one workflow.  
- [ ] **Filter:** `adminNotes = waitlist_signup` and `status = pending`.  
- [ ] **GDPR-style requests:** Process for delete/export (even if manual at first).

### Observability

- [ ] **Client errors:** Sentry or CloudWatch RUM (optional).  
- [ ] **API errors:** AppSync logging / Lambda if you add notifications later.

### Marketing

- [ ] **Analytics:** Plausible, GA4, or PostHog — privacy policy disclosure if needed.  
- [ ] **Open Graph / SEO:** Title and meta for `/` and `/join`.
